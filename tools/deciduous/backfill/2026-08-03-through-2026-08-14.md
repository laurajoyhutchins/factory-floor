## Portfolio visibility stays read-only and source-neutral

**Observation**

Portfolio state is useful in the operator surface, but Factory Floor must not acquire portfolio mutation authority merely because it displays that state.

**Decision**

Expose a read-only, source-neutral Portfolio Control Plane view while preserving Factory Floor execution authority and keeping portfolio mutation outside the browser surface.

**Action / evidence**

- `c377a86f0a1c4bec04e6e5c4f0f0578995d9f46b` — `feat: add Portfolio Control Plane view (#147)`

**Revisit**

Browser-delivered credentials would blur the read boundary and create an avoidable secret-distribution path.

**Decision**

Keep Portfolio reads behind validated configuration and safe same-origin proxy support; do not ship build-time Portfolio bearer credentials to the browser.

**Outcome / evidence**

- `fd6975fb585059463ec61b0d32bbdca4023284c5` — `fix(operator): harden Portfolio read boundary (#148)`

## Dynamic regions require durable admission, not optimistic scheduling

**Observation**

Reusable templates and child regions can declare work faster than bounded resources can safely admit it. Scheduling without durable admission would make capacity a transient worker assumption.

**Decision**

Persist hierarchical resource budgets and admission decisions in the authoritative runtime, and require admission before execution leases or external-action dispatch.

**Outcome / evidence**

- `42e571bd3b3b07b48b434310a46640b03dc3c18f` — `Add durable resource admission foundation (#154)`

The merged work also proves serialized concurrent admission, capacity return after cancellation and terminal execution, restart recovery, and hierarchical relinking.

## Capability vocabulary separates what exists from what is granted

**Observation**

A capability supported by the system is not the same fact as authority granted to a particular principal or execution.

**Decision**

Use distinct vocabulary for capabilities and capability grants so architecture, policy, and audit records do not collapse availability into authorization.

**Outcome / evidence**

- `0a67e73d61be97543dfe99f92bd144057f55b24a` — `docs: distinguish capabilities from capability grants (#158)`

## Template instantiation is promoted by concurrency and recovery proof

**Goal**

Make bounded dynamic child regions safe under concurrent creation, failed activation, and later consumption.

**Action**

Exercise PostgreSQL-backed template instantiation through concurrent and negative-path integration contracts, including recovery after failed activation and canonical child-region consumption.

**Outcome / evidence**

- `06f758dc4efc41c066290161c2ad5689e9f5df06` — `Prove template instantiation concurrency and child-region consumption (#159)`

## Routine integration can rely on delegated evidence instead of owner clearance

**Observation**

Requiring routine owner clearance for every otherwise eligible integration makes human approval carry authority that can instead be represented by bounded, reviewable evidence.

**Decision**

Represent integration eligibility declaratively and require trusted delegated integration evidence. Keep agent handoff state descriptive rather than embedding action instructions.

**Outcome / evidence**

- `33eb4bf7bc014d688a54e4272ded52486f81e002` — `Replace routine owner clearance with delegated integration evidence (#162)`

## External GitHub effects stay behind a scoped adapter

**Goal**

Allow bounded GitHub side effects without letting provider-specific behavior leak into the runtime authority model.

**Decision**

Use a scoped GitHub external-action adapter for the supported operation surface, with explicit repository and ref validation.

**Outcome / evidence**

- `364e5d44696846c930fa1d9547da3b45c915a24a` — `Add scoped GitHub external-action adapter (#160)`

## Verification belongs to the repository, not the CI provider

**Observation**

Hosted CI can execute verification, but the provider should not define what repository verification means.

**Decision**

Expose Factory Floor's existing complete verification gate through Repository CI Contract v1 without changing the underlying verification behavior.

**Outcome / evidence**

- `27a13c16ff4896f6d88e5109b8248b98afa2eae6` — `Adopt repository CI contract v1 (#168)`
